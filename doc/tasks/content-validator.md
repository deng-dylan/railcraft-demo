# ContentValidator 最小任务清单

> 设计依据：`doc/detailed-design.md` 第 5.6、7.2、13.2 节  
> 模块目标：对三份原始 JSON 字典执行结构、字段、引用、顺序和依赖校验，并一次返回可定位的问题集合。

## 边界

- 负责：校验规则、稳定错误码、JSON 路径、问题聚合。
- 不负责：文件读取、JSON 解析、DTO 转换、场景资源加载、业务流程。
- 前置条件：AR-001 至 AR-004 完成，GUT 可运行。
- 输出契约：`validate(raw_questions, raw_parts, raw_recipes) -> Array[ValidationIssue]`。

## 最小任务

- [x] **CV-001 建立校验问题类型。** 创建 `ValidationIssue`，包含 `code`、`json_path`、`message`、`severity`；添加构造和字段测试。验证：只运行该测试并通过。
- [x] **CV-002 建立校验器空壳。** 创建 `ContentValidator.validate()`，对三个空但类型正确的根字典返回问题数组，不抛出异常。验证：空输入测试通过且脚本可加载。
- [x] **CV-003 校验根结构和 schema_version。** 分别覆盖根对象缺失、数组缺失、版本缺失和版本不为 1。验证：每种输入返回预期错误码与路径。
- [x] **CV-004 校验必填字段及字段类型。** 按问题、零件、组件和整车配方逐类检查；一次任务只修改此规则组。验证：缺字段和错误类型夹具测试通过。
- [x] **CV-005 校验题目局部规则。** 检查题目 ID、四个非空选项、0 基正确答案索引、解析、来源三字段和奖励 ID。验证：每条规则各有正反例。
- [x] **CV-006 校验 ID 格式与唯一性。** 检查 `[a-z0-9_]+`，分别检测题目、零件、组件重复。验证：重复项全部被报告且路径准确。
- [x] **CV-007 校验跨文件引用。** 检查奖励零件、零件所属组件、组件零件和整车组件引用；检查每个零件恰好被一道题奖励并属于一个配方。验证：缺失和重复覆盖测试通过。
- [x] **CV-008 校验顺序和内容覆盖。** 检查题目、零件、组件顺序连续无重复，题目顺序与奖励零件顺序一致，整车覆盖全部组件。验证：断号、乱序和遗漏夹具测试通过。
- [x] **CV-009 校验安装依赖图。** 实现确定性的环检测，报告 `DEPENDENCY_CYCLE`；覆盖自环、双节点环、长环和合法单链。验证：环检测单元测试通过。
- [x] **CV-010 完成聚合与回归。** 确保一次校验能返回多个独立问题，错误码稳定，合法首版夹具无问题。验证：`test_content_validator.gd` 全部通过，执行 `gdformat --check` 和 `gdlint` 无新增问题。
