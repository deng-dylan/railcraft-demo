# RailCraft Unity v0.1 范围基线

- 文档版本：`v0.1`
- 目标平台：Windows x86_64
- 冻结日期：2026-08-01

本文是 RailCraft Unity 第一版测试版的范围基线。历史 Godot 内容仅保留为参考；Unity 运行时不会加载 Godot 场景、脚本或 `res://` 路径。下列 `GC-01` 至 `GC-28` 与实施计划的 28 条 Global Constraints 一一对应，任何发布候选都必须逐条验收。

## 全局约束（28/28）

| ID | 冻结约束 | v0.1 实施边界 |
|---|---|---|
| GC-01 | 可执行文件仅面向 Windows x86_64。 | 唯一发布目标为 `StandaloneWindows64`，交付入口为 `Builds/Windows/RailCraft.exe`。 |
| GC-02 | 使用 Unity Editor `6000.3.21f1`，提交 `ProjectSettings/ProjectVersion.txt` 与 `Packages/packages-lock.json`。 | 不接受编辑器迁移后生成的发布候选；包解析结果必须随源码保留。 |
| GC-03 | 使用 URP 与 Linear 色彩空间；v0.1 不混入 HDRP、Built-in Render Pipeline、UI Toolkit 或其他输入框架。 | 渲染使用 URP `17.3.x`，界面使用 uGUI，输入使用 Input System。 |
| GC-04 | 交互车辆语境为 CR400AF，交互转向架为 SWM-400E1 动力转向架。 | 引导文案、流程内容和模型契约统一使用这两个身份。 |
| GC-05 | SWT-400E1 拖车转向架内容留待后续版本。 | v0.1 不提供 SWT-400E1 流程、模型或交互入口。 |
| GC-06 | 场景设定为列车制造工厂。 | 工厂包含装配区、落车区、调试台、检验工位、放行区和背景轨道。 |
| GC-07 | 交互车体为简化动力中间车；CR400AF 风格头车只用于静态背景和最终英雄视角。 | 头车无碰撞体、拖拽组件和装配职责。 |
| GC-08 | 只实现引导式装配，不提供自由装配。 | 题目门禁、当前步骤和唯一匹配接口共同约束流程。 |
| GC-09 | 只使用键盘和鼠标。 | 鼠标完成选择、拖拽和镜头操作，WASD/方向键移动观察中心。 |
| GC-10 | 镜头支持环绕、平移和缩放；可拖拽零件保持作者设定旋转，不提供旋转控制。 | 右键环绕、中键平移、滚轮缩放；左键拖拽期间锁定镜头并持续恢复零件旋转。 |
| GC-11 | 唯一可改变流程进度的 3D 交互为拖放。 | 正确答案只解锁当前步骤；流程步骤只有在正确拖放并完成吸附后计入进度。 |
| GC-12 | 装配深度为子系统级，不实现螺栓、扭矩工具、配合公差或单个紧固件。 | 15 个步骤均使用模块、车体或任务卡级对象。 |
| GC-13 | 完成动力转向架子系统装配、车体落车、初次调试、整改、检验、二次调试和投入使用的宏观闭环。 | 冻结流程共 15 步，完整运行使用 48 道知识准备题。 |
| GC-14 | 调试失败必须明确标为教学占位，不得表述为已验证的 SWM-400E1 故障。 | 固定异常文案说明其教学演示用途，并明确不代表真实故障结论。 |
| GC-15 | 成员流程图只作为可替换的暂定顺序，通过 JSON 提供运行时内容。 | `flow.v1.json` 保存 15 步顺序、资产键、目标 ID 和题目分配；后续内容版本可替换 JSON。 |
| GC-16 | 使用 `50道选择+30道判断.doc` 冻结出的全部 48 道题：40 道单选、8 道判断。 | 运行时 ID 固定为 `q001` 至 `q048`，每题在完整流程中恰好使用一次。 |
| GC-17 | v0.1 保留冻结题目的题干、选项和正确答案。 | 原件、UTF-8 审阅转写、运行时 JSON 与交付清单共同构成内容基线；修订需创建新内容版本。 |
| GC-18 | 题库界面不显示引用或来源字段。 | 题目面板只显示阶段、题号、题干、选项和作答反馈。 |
| GC-19 | 错误答案允许重试；当前步骤全部答对后才解锁对应拖拽。 | 错答保留同一题目；末题答对触发一次解锁事件。 |
| GC-20 | 不计算或显示分数、正确率、等级、排名或知识掌握度。 | 状态与 UI 契约均不包含上述统计面。 |
| GC-21 | 不实现存档、继续游戏、账户、联网、分析、音频、非 Windows 发布目标、XR、触控或多人功能。 | 流程只存在于当前内存会话；项目禁用音频，主菜单无继续入口。 |
| GC-22 | 包含开始、操作说明、仅限画质/窗口模式的设置、重置流程和退出。 | 设置仅在当前运行内生效，不写入 `PlayerPrefs`。重置清空流程、已安装对象与活动交互。 |
| GC-23 | 运行时内容完全本地，不依赖网络连接。 | 题库、流程、prefab、场景和材质均随 Build 目录交付。 |
| GC-24 | 可使用占位或公开低多边形模型；工程尺寸和车型专用几何只能来自责任成员或经过验证的技术来源。 | 当前占位几何不承载工程尺寸结论；生产资产须通过身份、单位、尺寸、坐标、LOD 和材质门禁。 |
| GC-25 | 已提供的 `wheel.SLDPRT` 在尺寸与 SWM-400E1 适用性确认前保持候选源资产状态。 | 未收到 STEP AP242/Parasolid、名义尺寸与身份声明前，不生成生产 `WheelRuntime.prefab`。 |
| GC-26 | UI 语言为简体中文。 | 主菜单、操作说明、问题、反馈、工艺提示和完成界面均以简体中文验收。 |
| GC-27 | 跟踪源码、优化后的运行时资产、测试、清单和审阅图；原始交付二进制保留在被忽略的 `deliveries/**/release/**`。 | `Library/`、`TestResults/` 和 `Builds/` 同样不进入源码提交；最终验收证据保存在 `Artifacts/Acceptance/`。 |
| GC-28 | 当前执行默认使用主线内联方式；只有用户明确请求时才使用子代理。 | 本条约束用于项目实施治理，不改变运行时功能或交付内容。 |

## 固定产品流程

v0.1 使用 `flow.v1.json` 定义的 15 个有序步骤：11 个动力转向架子系统步骤、车体落车、初次调试、整改与检验、放行。初次调试固定进入教学占位异常，随后执行整改、检验和无重复题目的二次调试，最终投入使用。

全部题目在源顺序中分配给 15 个阶段。界面将这些题称为“知识准备题”，不宣称混合领域题目都直接描述当前装配动作。

## 明确排除项

v0.1 不包含以下能力：

- 自由装配、零件旋转、物理力驱动装配；
- 紧固件、扭矩、配合、公差、材料、质量和安全极限计算；
- 存档/继续、用户账户、云同步、联网内容、遥测或分析；
- 得分、正确率、等级、排名和知识掌握度；
- 音乐、音效、语音、触控、手柄、非 Windows 发布目标、XR 和多人模式；
- SWT-400E1 拖车转向架交互内容；
- 经验证的 SWM-400E1 工厂作业参数、检验标准和故障诊断结论。

## 工程与模型边界

占位模型只用于教学流程、视觉构图和交互验证。SWM-400E1 专用尺寸、安装接口、轮型、悬挂、驱动、制动、传感器、吊装点和工艺后果必须由责任成员或可核验技术来源提供。不得从预览图、渲染图或语言模型输出推导缺失工程值。

候选 `wheel.SLDPRT` 当前仍缺少中性格式、毫米单位确认、名义轮径/轮宽/轮毂孔径、轴向原点说明和车型适用声明。详细交接门禁见 `Documentation/ModelHandoff.md`。

## 完成门禁

发布候选只有在以下条件全部满足后才能标记为 v0.1 验收通过：固定编辑器无迁移打开、完整 EditMode/PlayMode 自动化通过、Windows x86_64 构建成功、48 题与 15 步新运行通过、调试闭环可见、镜头与固定旋转拖放可用、排除功能未出现、目录式 Build 可离线运行，以及验收报告、12 张截图、性能记录和可执行文件 SHA-256 齐全。
