# RailCraft 第三人称流程白盒

> **状态：当前开发主线。** 本文是第三人称白盒的现行范围、流程与替换契约。
> Unity 固定视角 v0.1 已冻结为验收基线，Godot `v0.1.0-demo` 已冻结为历史
> Demo；两者不覆盖本文的当前定义。

- 目标：验证“探索—答题—拾取—库存—分级拼装—落车—调试检验—投入使用”的完整玩法闭环。
- 引擎：Unity `6000.3.21f1`、URP、Input System。
- 平台：Windows x86_64，键盘与鼠标。
- 边界：场景使用方块、圆柱、胶囊等基础几何体；后续可由 Blender prefab 替换视觉资产。
- 兼容：现有 `Bootstrap`、`Factory` 与 v0.1 验收内容继续保留；项目默认场景切换到白盒，两个版本使用各自的显式构建入口。

## 版本关系

- 当前开发主线：`Assets/RailCraft/ThirdPerson/` 与本白盒场景；新玩法、题库映射、

## 玩家流程

1. 玩家在主菜单选择本轮装配方案，然后使用 `WASD` 移动、`Shift` 奔跑，鼠标控制第三人称镜头。
2. 靠近零件知识工位按 `E` 打开题目。选择题显示 4 个选项，判断题显示“正确/错误”2 个选项。
3. 答对后解锁工位上的世界零件；再次按 `E` 拾取，零件进入库存。
4. 玩家按流程图在四个基础装配台逐件安装零件，得到轮对轴箱、构架、一系悬挂装置和二系悬挂装置。
5. 轮对轴箱、构架和一系悬挂装置组成所选方案的转向架构体。
6. 转向架构体、车体、二系悬挂装置和中央牵引装置完成所选方案的落车。
7. 落车后进入调试判定。首次调试在白盒中固定进入失败分支，玩家需要依次完成重新调试、检验和复测。
8. 复测成功后触发“车辆投入使用”判定、成绩结算并开放工程知识图鉴；最终出厂展示仍进入完整复兴号展示场景。

错误答案允许重试。题目奖励、拾取、零件安装、子装配安装和调试操作均保持幂等，重复交互不会复制物品或增加进度。

### 可玩装配方案

主菜单提供四个方案：复兴号教学装配、地铁简化转向架、Y25 欧洲货运转向架和教学概念
转向架。它们共享已经验证的题目、零件库存、安装槽、落车输入和调试状态机，因此切换
方案不会改变流程规则；方案值会写入存档并在继续游戏时恢复。后面三个方案的 CAD 源文件
完成 FBX/GLB 网格化后，放入 `Art/Models/VariantModels/` 对应插槽，重新生成白盒即可替换
当前参考模型。尚未完成网格化时，场景使用低风险示范件占位，并在 HUD 与工位标签中明确
显示方案和资产状态。

## 装配依赖图

```text
车轴 + 车轮 + 轴承
  → 轮对轴箱 ┐

制动装置 + 牵引拉杆 + 传感器座
  → 构架 ────┼→ 转向架构体 ┐

一系弹性元件 + 一系定位元件 + 一系减振元件
  → 一系悬挂装置 ┘          │
                              ├→ 落车 → 调试判定
二系弹性元件 + 高度控制元件 + 二系减振元件
  → 二系悬挂装置 ───────────┤
                              │
车体 + 中央牵引装置 ─────────┘

调试失败 → 重新调试 → 检验 → 返回调试判定
调试成功 → 投入使用
```

内部 ID 会区分一系和二系的同名元件，避免弹性元件或减振元件串装。

## 题库

题库来自用户提供的 `50道选择+30道判断.doc`。文档正文实际包含：

- 50 道四选一；
- 8 道判断题；
- 每题均带答案和解析。

因此当前导入 58 道题。文件名所指的另外 22 道判断题在原文中没有正文，项目没有自行补写。题目按零件工位分成 14 个循环题池，重新开始时会切换下一题。展示选项会做确定性轮换，同时把点击位置映射回原题正确答案索引。

## 内容规模

- 14 个答题与零件拾取工位，每个工位对应 1 个可入库零件，共 14 个零件；
- 6 个装配节点：4 个基础零件装配台、1 个转向架构体装配台、1 个落车工位；
- 调试判定、重新调试、检验 3 个流程工位；
- 1 个投入使用完成界面。

装配进度统一计算为 23 步：14 次零件安装、5 次子总成安装和 4 次调试推进。

## v0.2 系统

- 主菜单提供开始游戏、继续游戏、设置和退出；游戏中按 `ESC` 打开暂停菜单，再按
  `ESC` 返回游戏，设置页按 `ESC` 先保存并返回暂停菜单。答题、知识弹窗和结算界面
  占用输入时不会被暂停菜单抢占；设置保存音效音量与画质等级。
- 会话自动保存答题统计、零件、库存、装配层级、调试阶段和流程时间；进入主菜单、
  应用暂停或退出时停表，继续游戏后恢复累计，因此结算用时只包含有效装配时间。
  继续游戏会校验快照，损坏存档会被拒绝并清理。
- 有限状态机使用“待装配 → 进行中 → 完成”，顶部同步显示第 X 步/共 23 步、
  完成度百分比和当前状态。
- 成绩结算显示装配用时、答题正确率、0–100 分和初级/中级/高级工程师评定。
- 工程知识数据包含 58 条题目解析、14 条零件知识、6 条装配知识、4 条调试知识
  和 1 条整车总览，共 83 条；流程中逐步解锁，整车完成后开放图鉴入口。
- 一键重玩会清空流程、计时、统计、库存、装配和调试状态，并开始一轮新训练。
- 当前可交互工位使用脉冲高亮，成功与失败显示不同颜色；关键总成完成后镜头短暂
  聚焦装配细节，再恢复原第三人称视角。

## 打开与构建

- 场景：`Assets/RailCraft/ThirdPerson/Scenes/ThirdPersonWhitebox.unity`
- 重新生成白盒：Unity 菜单 `RailCraft > Third Person Whitebox > Rebuild Scene`
- 构建 Windows 版：Unity 菜单 `RailCraft > Third Person Whitebox > Build Windows x86_64`；该入口会先重建生成场景，避免打包旧场景。
- 本地可执行文件：`Builds/Whitebox/RailCraftWhitebox.exe`

拉取生成器源码变更后，直接在编辑器进入 Play 前应先执行一次“重新生成白盒”；
Windows 构建入口已内置该步骤。下列证据以各文件记录的批次为准，本批只有重新完成
Unity 测试、Windows 构建和成品冒烟后才能更新为 v0.2 最终验收证据。

当前白盒的可复核证据位于 `Artifacts/Whitebox/Acceptance/`：

- `build.log`：独立 Windows x86_64 构建日志；
- `editmode.xml`：自动化测试结果；
- `player-smoke.log`：成品流程冒烟记录；
- `screenshots/01-complete.png`：完成态截图。

成品自动烟测可追加 `-whitebox-smoke-variant=<方案 key>`，用于分别验证四个装配方案的
完整答题、拾取、装配、落车、调试和重置闭环。

冻结固定视角 v0.1 的证据继续保存在 `Artifacts/Acceptance/`，两个目录分别维护，
不相互覆盖。

## Blender 资产替换契约

正式资产通过 prefab 替换白盒几何，玩法代码不依赖网格名称或网格层级。每个替换资产需满足：

- Unity 世界单位为米，prefab 根节点保持位置与旋转为零、缩放为一；
- 原点位于装配基准点，朝向遵守项目模型交接规范；
- 渲染网格位于独立视觉根节点下；
- 碰撞体使用简化基础体或凸包，不直接使用高模非凸动态碰撞；
- 提供稳定的 `partId` 或 `moduleId` 映射；
- LOD、PBR 材质和纹理均可在不改玩法状态机的情况下替换；
- 吸附位置由场景中的安装槽 Transform 决定。

生产尺寸、结构身份、单位与轴向继续遵守 `Documentation/ModelHandoff.md`。

完成 Blender 视觉替换后，避免直接重跑 `Rebuild Scene`，该命令会按白盒定义重新生成场景。建议复制为正式美术场景，或先把正式模型接成 prefab 配置，再扩展生成器。

## 迭代与提交规则

- 每批改动只承担一个可验证目标，例如题库、流程、交互、场景、美术替换或验收；
  同批更新相应测试和本文。
- 测试、Windows 构建和成品冒烟通过后创建独立提交，再及时推送当前功能分支。
- 该批代码生成的最终日志、XML、校验值和代表性截图与代码同批提交；
  `Library/`、`Builds/`、`TestResults/` 和中间截图保持本地可再生状态。
- 提交前检查 `git diff` 和 `git status --short`，避免混入冻结 v0.1、Godot、
  原始交付或其他批次的改动。

## 白盒验收

- 玩家可从出生点连续完成全部流程，无需编辑器操作；
- UI 打开时角色与镜头输入锁定，关闭后恢复；
- 4 选项和 2 选项题目均能正确显示与判定；
- 错答不解锁零件，答对只解锁一次；
- 未答对不能拾取，重复拾取不能复制库存；
- 缺少零件时基础装配不能推进；
- 未完成的子装配不能装入上层装配；
- 四项落车输入缺少任意一项时不能完成落车；
- 落车完成后仍需执行调试流程；
- 失败、重新调试、检验和复测回路可完整操作；
- 只有调试通过后才显示“投入使用”；
- 主菜单、继续游戏、音效与画质设置可用，损坏存档不会进入游戏；
- 顶部进度、百分比与“待装配/进行中/完成”状态和真实会话一致；
- 完成界面展示用时、正确率、得分和工程师等级，图鉴只在整车完成后开放；
- 主菜单停留、应用暂停和离线时间不计入完成界面的装配用时；
- 可交互高亮、结果颜色反馈和关键节点镜头切换均可恢复原状态；
- 重置后题目轮换，解锁、库存、装配、落车和调试状态全部清空；
- EditMode 测试、Windows 构建与构建成品自动冒烟验证通过。
