# GameFlowManager 最小任务清单

> 设计依据：`doc/detailed-design.md` 第 6、7.7、8 节  
> 模块目标：以唯一状态机编排答题、奖励、装配和动画完成事件，并通过信号隔离具体表现层。

## 边界

- 负责：状态白名单、用户意图处理、领域调用顺序、表现请求信号、异步回调校验。
- 不负责：JSON、控件显隐、模型实例化和 Tween。
- 前置模块：`QuizManager`、`InventoryManager`、`AssemblyManager`、内容 DTO。

## 最小任务

- [x] **GF-001 创建 GameState 与转换白名单。** 定义 8 个状态和允许转换表。验证：允许与禁止转换各有测试。
- [x] **GF-002 实现依赖注入与 initialize。** 注入三个领域管理器和 Catalog，初始化后进入 `START`。验证：缺少依赖时返回明确错误。
- [x] **GF-003 实现开始与退出事件。** `request_start()` 发布第 1 题并进入 `QUIZ`；只允许 `START/END` 退出。验证：状态和信号顺序测试通过。
- [x] **GF-004 实现错误答案路径。** 在 `QUIZ/WRONG_FEEDBACK` 调用 Quiz，错误时显示固定文案且不调用库存。验证：记录型库存假对象调用数为 0。
- [x] **GF-005 实现正确答案路径。** 首次正确时只调用一次 `grant_part()`，进入 `CORRECT_FEEDBACK` 并发布解析。验证：重复答案不重复发放。
- [x] **GF-006 实现进入装配。** 仅在 `CORRECT_FEEDBACK` 验证奖励已拥有且等于预期零件，再发布 `assembly_preparation_requested`。验证：缺奖励和错误 ID 被拒绝。
- [x] **GF-007 实现零件点击处理。** 仅在 `ASSEMBLY` 调用 `begin_install()`，成功时发布一次吸附请求。验证：越序和动画中重复点击不发布请求。
- [x] **GF-008 实现普通吸附完成。** 校验回调 ID，提交安装，推进题目并发布下一题。验证：第 1、2、4、5、7、8 个零件路径正确。
- [x] **GF-009 实现吸附失败恢复。** 调用 `abort_pending_install()`，保持 `ASSEMBLY` 并发布可重试提示。验证：失败后再次点击可启动动画。
- [x] **GF-010 实现组件完成路径。** 第 3、6、9 个零件提交后进入 `COMPONENT_COMPLETE` 并发布一次对应组件动画。验证：组件 ID 与配方一致。
- [x] **GF-011 实现组件动画回调。** 前两个组件完成后推进题目；第三个组件后进入 `FINAL_ASSEMBLY`。验证：旧组件 ID 回调被忽略。
- [x] **GF-012 实现最终完成路径。** 最终动画完成后进入 `END` 并发布整车名称。验证：提前回调无法进入 END。
- [x] **GF-013 类型化全部输出信号。** 实现详细设计列出的题目、反馈、装配、组件、最终和错误信号。验证：记录型监听器收到正确参数和顺序。
- [x] **GF-014 覆盖非法与重复事件。** 对每个状态调用不允许事件，断言状态与领域快照不变。验证：表驱动测试全部通过。
- [x] **GF-015 完成流程回归。** 跑通“全部一次正确”和“每题先错后对”两条 9 题路径，验证所有状态可到达 END。验证：`test_game_flow*.gd` 全部通过，格式和 lint 通过。
