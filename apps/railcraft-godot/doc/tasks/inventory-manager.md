# InventoryManager 最小任务清单

> 设计依据：`doc/detailed-design.md` 第 2.5、7.5 节  
> 模块目标：维护已获得零件集合，并保证奖励发放幂等。

## 边界

- 负责：已知零件集合、拥有集合、发放结果和查询。
- 不负责：判断答案、安装零件、保存进度、更新 UI。
- 前置模块：`ContentRepository` 提供 `PartData`；单测可直接构造最小零件。

## 最小任务

- [x] **IM-001 创建 GrantResult。** 定义 `GRANTED`、`ALREADY_OWNED`、`UNKNOWN_PART`。验证：结果枚举测试通过。
- [x] **IM-002 实现 configure。** 从零件列表建立已知 ID 集合，并清空拥有集合。验证：重复 ID 由上游保证，空列表可配置。
- [x] **IM-003 实现首次发放。** 已知且未拥有的 ID 加入集合并返回 `GRANTED`。验证：拥有数量从 0 变 1。
- [x] **IM-004 实现幂等发放。** 重复发放同一 ID 返回 `ALREADY_OWNED`，集合数量不变。验证：连续调用测试通过。
- [x] **IM-005 实现未知 ID 保护。** 返回 `UNKNOWN_PART` 且不修改集合。验证：未知值和空字符串测试通过。
- [x] **IM-006 实现查询和重置。** `has_part()`、`get_owned_part_ids()` 和 `reset()`；返回数组副本。验证：修改返回数组不影响内部状态。
- [x] **IM-007 完成库存回归。** 覆盖 9 个零件依次发放、重复发放和重置。验证：`test_inventory_manager.gd` 全部通过，格式和 lint 通过。

## 模块完成标准

- [x] 同一零件最多成功发放一次；
- [x] 未知零件不会进入拥有集合；
- [x] 模块无文件、场景和存档依赖；
- [x] 单独运行本模块测试全部通过；
- [x] 更新 [`progress.md`](progress.md) 中模块任务数和完成状态。
