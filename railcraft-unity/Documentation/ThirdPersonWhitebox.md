# RailCraft Unity ThirdPerson 标准实训

> **当前主线规格。** 本文定义 Windows x86_64 的 Unity ThirdPerson 标准实训范围、流程、替换契约与验收条件。
> 当前阶段是白盒之后的 Art Alpha；RC-EMU-01 是通用高速动车组标准工单，复兴号/和谐号只作为原创外观风格参考。

- 目标：验证“标准工单—知识确认—材料领取—分级拼装—落车—教学故障调试—检验”的完整实训闭环。
- 引擎：Unity `6000.3.21f1`、URP、Input System。
- 平台：Windows x86_64，键盘与鼠标。
- 边界：场景仍包含白盒和通用示范几何；正式视觉资产通过 Prefab/生成器逐步替换。
- 兼容：当前主线只维护 ThirdPerson；旧版本通过 Git tag 或本机归档恢复，不参与当前构建。

## 玩家流程

1. 玩家从主菜单开始通用高速动车组标准工单 `RC-EMU-01`，然后使用 `WASD` 移动、`Shift` 奔跑，鼠标控制第三人称镜头。
2. 靠近材料包知识工位按 `E` 打开题目。选择题显示 4 个选项，判断题显示“正确/错误”2 个选项。
3. 答完当前材料包的 2 道核心题后，一次解锁并领取整包输入；包内子部件进入“待装配输入”，但不分别占用领取动作。
4. 玩家按流程图在四个基础装配台各执行一次材料包装配，得到轮对轴箱、构架、一系悬挂装置和二系悬挂装置。
5. 轮对轴箱、构架和一系悬挂装置组成一套代表性转向架构体；同型第二套由配套生产线提供。
6. 转向架构体、车体落车材料包和二系悬挂装置完成动力中间车落车，完成态直接切换为带两套转向架的成品工况。
7. 落车后进入调试判定。首次判定明确标记为教学故障注入，玩家依次完成故障处理、检验和复测。
8. 复测成功后触发“标准实训完成”判定、成绩结算并开放工程知识图鉴；八编组展示使用通用高速动车组风格场景。

错误答案允许重试。题目奖励、拾取、零件安装、子装配安装和调试操作均保持幂等，重复交互不会复制物品或增加进度。

### 标准工单与扩展模型

普通玩家入口使用通用高速动车组标准实训线。复兴号风格、和谐号风格、地铁、货运和教学
概念件都属于独立构型登记；只有网格、工艺语义、来源和独立教学目标齐备后才形成扩展关卡。
旧存档仍可按兼容映射恢复，避免升级时丢失已有进度。

工厂按“知识确认与材料准备 → 子总成与转向架装配 → 落车、教学调试与检验”三段工艺区
布置。Factory Kit 继续作为车间建筑与设备背景，玩法工位围绕既有厂房净空排列，并通过
标准工单看板、区域底色和背墙编号表达流程方向。

## 装配依赖图

```text
车轴 + 车轮 + 轴承
  → 轮对轴箱 ┐

制动装置 + 牵引拉杆 + 传感器座
  → 构架 ────┼→ 转向架构体 ┐

一系弹性元件 + 一系定位元件 + 一系减振元件
  → 一系悬挂装置 ┘          │
                              ├→ 落车 → 调试判定
二系弹性元件 + 高度控制元件 + 二系减振元件
  → 二系悬挂装置 ───────────┤
                              │
车体 + 中央牵引装置 ─────────┘

教学故障注入 → 故障处理 → 检验 → 返回调试判定
复测成功 → 标准实训完成
```

内部 ID 会区分一系和二系的同名元件，避免弹性元件或减振元件串装。

## 题库

题库来自用户提供的 `50道选择+30道判断.doc`。文档正文实际包含：

- 50 道四选一；
- 8 道判断题；
- 每题均带答案和解析。

因此当前导入 58 道题。文件名所指的另外 22 道判断题在原文中没有正文，项目没有自行补写。
58 题按主题、材料包和审核状态维护；核心流程精选 10 题（每个材料包 2 题），其余题目作为备用题或知识图鉴内容。
展示选项会做确定性轮换，同时把点击位置映射回原题正确答案索引。题目数量不再决定工位或零件数量。

## 内容规模

- 5 个材料包级知识与领取工位，另有 1 个调试与检验流程模块；域模型保留 14 个可兼容子部件 ID；
- 6 个装配节点：4 个基础材料包装配台、1 个转向架构体装配台、1 个落车工位；
- 调试判定、重新调试、检验 3 个流程工位；
- 1 个标准实训完成界面，并提供八编组出厂展示入口。

装配进度继续由实际安装和调试节点计算；模块工位数量与题库题数相互独立。

## Art Alpha 标准实训系统

- 主菜单提供开始标准实训、继续实训、设置和退出；游戏中按 `ESC` 打开暂停菜单，再按
  `ESC` 返回游戏，设置页按 `ESC` 先保存并返回暂停菜单。答题、知识弹窗和结算界面
  占用输入时不会被暂停菜单抢占；设置保存音效音量与画质等级。
- 会话自动保存答题统计、零件、库存、装配层级、调试阶段和流程时间；进入主菜单、
  应用暂停或退出时停表，继续游戏后恢复累计，因此结算用时只包含有效装配时间。
  继续游戏会校验快照，损坏存档会被拒绝并清理。
- 有限状态机使用“待装配 → 进行中 → 完成”，顶部同步显示第 X 步/共 14 步、
  完成度百分比和当前状态。
- 成绩结算显示装配用时、答题正确率、0–100 分和初级/中级/高级工程师评定。
- 工程知识数据包含 58 条题目解析、14 条子部件知识、6 条装配知识、4 条调试知识
  和 1 条整车总览，共 83 条；流程中逐步解锁，整车完成后开放图鉴入口。
- 一键重玩会清空流程、计时、统计、库存、装配和调试状态，并开始一轮新训练。
- 当前可交互工位使用脉冲高亮，成功与失败显示不同颜色；关键总成完成后镜头短暂
  聚焦装配细节，再恢复原第三人称视角。
- 转向架构体完成后切换为 CW-200K 客车转向架参考模型；落车完成态使用两套同源
  参考模型。零件与子总成阶段继续保留语义低模，以支持逐件显隐和流程映射。

## Blender 资产替换契约

正式资产通过 prefab 替换白盒几何，玩法代码不依赖网格名称或网格层级。每个替换资产需满足：

- Unity 世界单位为米，prefab 根节点保持位置与旋转为零、缩放为一；
- 原点位于装配基准点，朝向遵守项目模型交接规范；
- 渲染网格位于独立视觉根节点下；
- 碰撞体使用简化基础体或凸包，不直接使用高模非凸动态碰撞；
- 提供稳定的 `partId` 或 `moduleId` 映射；
- LOD、PBR 材质和纹理均可在不改玩法状态机的情况下替换；
- 吸附位置由场景中的安装槽 Transform 决定。

生产尺寸、结构身份、单位与轴向继续遵守 `Documentation/ModelHandoff.md`。

完成 Blender 视觉替换时，先把正式模型接入 Prefab、配置或视觉工厂，再执行 `Rebuild Scene`。
生成场景只作为输出文件，不承载无法复现的手工修改。

## 迭代与提交规则

- 每批改动只承担一个可验证目标，例如题库、流程、交互、场景、美术替换或验收；
  同批更新相应测试和本文。
- 测试、Windows 构建和成品冒烟通过后创建独立提交，再及时推送当前功能分支。
- 该批代码生成的最终日志、XML、校验值和代表性截图与代码同批提交；
  `Library/`、`Builds/`、`TestResults/` 和中间截图保持本地可再生状态。
- 提交前检查 `git diff` 和 `git status --short`，避免混入归档、原始交付或其他批次的改动。

## 白盒验收

- 玩家可从出生点连续完成全部流程，无需编辑器操作；
- UI 打开时角色与镜头输入锁定，关闭后恢复；
- 4 选项和 2 选项题目均能正确显示与判定；
- 错答不解锁材料包，答完包内门禁题后只解锁一次；
- 未完成门禁不能领取，重复领取不能复制库存；
- 缺少材料包时基础装配不能推进；
- 未完成的子装配不能装入上层装配；
- 两个已完成子总成或车体落车材料包缺少任一输入时不能完成落车；
- 落车完成后仍需执行调试流程；
- 失败、重新调试、检验和复测回路可完整操作；
- 只有复测通过后才显示“标准实训完成”；
- 主菜单、继续游戏、音效与画质设置可用，损坏存档不会进入游戏；
- 顶部进度、百分比与“待装配/进行中/完成”状态和真实会话一致；
- 完成界面展示用时、正确率、得分和工程师等级，图鉴只在整车完成后开放；
- 主菜单停留、应用暂停和离线时间不计入完成界面的装配用时；
- 可交互高亮、结果颜色反馈和关键节点镜头切换均可恢复原状态；
- 重置后题目轮换，解锁、库存、装配、落车和调试状态全部清空；
- EditMode 测试、Windows 构建与构建成品自动冒烟验证通过。
