# ADR-0001：项目总仓库与应用工程的边界

- 状态：已采纳
- 日期：2026-07-21

## 背景

团队需要在同一处管理赛项资料、产品想法、技术评审、外部 Demo 和实际可运行的应用工程。Godot Demo 已有独立提交历史，项目总仓库也已完成初始目录整理。

## 决策

项目总仓库统一保存项目级资料、原型治理记录和主线应用源码。Godot 工程直接纳入 `apps/railcraft-godot`，原 Demo 的提交历史通过 Git 合并历史继续保留。外部 Demo 采用原型目录和交付登记保存可审计资料。

## 结果

- 项目资料能够与应用代码一起被检索、评审和追溯。
- Godot 工程保留独立的构建、测试和发布流程，并与项目资料使用同一仓库版本线。
- GOOD2 等跨引擎方案不会进入主 Demo 的构建链路。
- 团队一次克隆即可取得项目资料、原型快照和完整主应用源码。

## 约束

- 不在主 Demo 中嵌入第二套游戏引擎或运行时。
- 原始交付包不进入 Git 历史；其版本、校验值和来源记录写入 `deliveries/`。
- 需要将原型能力纳入主线时，按主工程的数据、许可和测试标准重新实现。
