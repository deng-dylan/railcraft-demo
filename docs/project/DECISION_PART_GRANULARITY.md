# 决策：材料包与子部件粒度

编号：`FLOW-002`
日期：2026-09-04
状态：已采用

## 结论

主线玩家流程采用 5 个材料包，调试与检验作为独立流程模块：

| 材料包 | 内部子部件 | 玩家动作 | 知识门禁 |
| --- | --- | --- | --- |
| 轮对轴箱 | 车轴、车轮、轴承 | 领取 1 次，装配 1 次 | 2 题 |
| 构架与制动/牵引 | 制动装置、牵引拉杆、传感器座 | 领取 1 次，装配 1 次 | 2 题 |
| 一系悬挂 | 一系弹性、定位、一系减振 | 领取 1 次，装配 1 次 | 2 题 |
| 二系悬挂 | 二系弹性、高度控制、二系减振 | 领取 1 次，装配 1 次 | 2 题 |
| 车体落车 | 车体、中央牵引装置 | 领取 1 次，落车提交 1 次 | 2 题 |

因此首个完整演示使用 10 道核心门禁题。题库中的其余题目继续保留为备用题和知识图鉴，
题目数量不再决定模型、工位或装配次数。

## 为什么保留 14 个 PartId

14 个 `PartId` 仍然用于以下内部职责：

- 装配配方中的真实组成关系；
- 完成态模型的子件显隐和后续替换；
- 旧存档与旧适配器的读取；
- 未来需要逐件检查时的扩展接口。

它们不再作为当前主线的 14 个领取目标。材料包 API 会原子解锁、领取和安装包内子件，
画面可以展示子件分解，玩家只面对一个工艺节点。

## 明确取消的做法

- 不为每道题创建一个新零件或新工位；
- 不把传感器座、定位元件、高度控制元件的占位几何包装成车型专用件；
- 不用题号、零件枚举数量证明工程真实性；
- 不为了保持旧的 23 步数字而继续增加交互。

## 当前验收口径

1. 五个 `QuizPartStation` 必须标记为材料包模式，每个包只出现一次领取动作；
2. 四个基础 `ModuleAssemblyStation` 使用一次批量安装，内部子件同时落位；
3. 落车工位把车体与中央牵引装置作为一个材料包输入，和两个已完成子总成一起提交；
4. 进度显示按包和工艺节点计算，当前总步数为 14；
5. 旧逐件 API 和快照仍可用，旧测试不因本次玩家层收敛而失效；
6. 新模型只需先满足五个包的代表性视觉和完成态，缺失的专用子件不阻塞 Art Alpha。

## 内容版本

结构快照继续使用 schema 1，同时写入四个独立内容标识：

| 内容 | 当前版本 |
| --- | --- |
| 58 题原始题库 | `question-bank-user-doc-58-v1` |
| 10 题核心门禁集合 | `core-packages-10-v1` |
| 5 个材料包配方 | `work-packages-5-v1` |
| 旧逐件奖励路由 | `legacy-reward-routing-v2` |

旧存档没有这些字段时按兼容路径读取；带有未知非空版本的存档会明确拒绝，后续修改核心题或
材料包配方前必须先增加迁移规则，避免静默误解 `1/2` 门禁进度。

## 后续升级条件

只有当竞赛评分表或责任工程师明确要求逐件检验时，才新增“详细拆解模式”。详细模式应作为
独立表现层，不能重新改变标准工单的包级流程和存档语义。
